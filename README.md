# AI Quant Bot v25.0 — Funding Rate + Portfolio Risk Cap Edition

پاسخ به درخواست «بدون باگ + هر بهبود رایگان و قابل‌اجرا که به ذهنم می‌رسد» —
با همان اصل همیشگی: فقط چیزی اضافه می‌شود که واقعاً رایگان، واقعاً قابل‌اجرا از
گوشی/گیت‌هاب، و صادقانه توضیح داده‌شده باشد.

## 🔍 بررسی باگ (نتیجه: چیز بحرانی جدیدی پیدا نشد)

کل کد (۸ فایل، ~۱۷۰۰ خط) خط‌به‌خط مرور شد. منطق امتیازدهی، مدیریت state،
مدیریت معاملات باز، و workflow گیت‌هاب همگی درست کار می‌کنند — باگ‌های واقعی
قبلی (v14 تا v23) قبلاً رفع شده بودند. یک نقطهٔ ضعف کوچک (نه یک باگ فعال، بلکه
یک ریسک بالقوه) پیدا و رفع شد:

**نوشتن state ناکامل در صورت قطع ناگهانی اجرا**: `save_state` قبلاً مستقیم روی
فایل اصلی می‌نوشت. اگر GitHub Actions دقیقاً وسط نوشتن فایل کنسل/قطع می‌شد
(مثلاً به‌خاطر timeout)، فایل state می‌توانست نیمه‌نوشته و خراب بماند — و چون
نسخهٔ backup هم در اجرای بعدی از همین فایل خراب گرفته می‌شود، این می‌توانست
هر دو نسخه را خراب کند. الان اول در یک فایل موقت نوشته می‌شود و فقط بعد از
موفقیت کامل، به‌صورت اتمی (یک عملیات غیرقابل‌قطع در سطح سیستم‌عامل) جایگزین
فایل اصلی می‌شود.

## ✅ دو بهبود جدید (هر دو رایگان، بدون نیاز به API Key جدید)

### ۱. Funding Rate (نرخ فاندینگ فیوچرز پرپچوال)

همان ایده‌ای که در v24 به‌عنوان «قدم بعدی» یادداشت شده بود. از اندپوینت رایگان و
بدون کلید Binance (`fapi/v1/premiumIndex`) خوانده می‌شود. وقتی این نرخ خیلی
مثبت است یعنی معامله‌گران فیوچرز به‌شدت روی Long شلوغ/پرهزینه شده‌اند —
تجربهٔ بازار نشان می‌دهد این وضعیت اغلب مقدمهٔ یک اصلاح/Long Squeeze است، پس
امتیاز کمی (نه تعیین‌کننده، فقط یک اصلاح‌کنندهٔ ملایم) در جهت مخالف اضافه
می‌شود؛ نرخ خیلی منفی هم برعکس. اگر این اندپوینت هم در دسترس نباشد، ربات
بدون خطا و بدون تأثیر روی امتیاز ادامه می‌دهد (Fail-open، هرگز سیگنال را
مسدود نمی‌کند). در پیام تلگرام هم نمایش داده می‌شود.

### ۲. سقف معاملات هم‌زمان (MAX_CONCURRENT_TRADES)

چون خیلی از این ۱۰ نماد (مثلاً BTC/ETH/BNB) اغلب هم‌جهت حرکت می‌کنند، بدون این
سقف ممکن بود ربات در یک چرخه چند سیگنال هم‌بسته را هم‌زمان باز کند — که ظاهراً
تنوع است ولی عملاً همان یک ریسک را چند بار تکرار کردن است. پیش‌فرض: حداکثر
۴ معاملهٔ باز هم‌زمان در کل پورتفولیو (قابل تغییر با GitHub Variable
`MAX_CONCURRENT_TRADES`؛ برای غیرفعال‌کردن مقدار `0`).

## ❌ ایده‌هایی که بررسی و آگاهانه رد شدند

- **BTC Dominance (از CoinGecko)**: بررسی شد، ولی برخلاف Funding Rate، تعیین
  یک آستانهٔ معنادار و جهت‌دار برای «چقدر Dominance بالا/پایین یعنی چه» بدون
  بک‌تست تاریخی واقعی حدس‌وگمان محض می‌شد — ریسک بدتر کردن سیگنال به بهانهٔ
  بهبود. ترجیح دادم به‌جای این حدس، منتظر تجمیع دادهٔ گزارش روزانهٔ خودتان
  (Win Rate/Profit Factor) بمانم که یک تست A/B واقعی روی این ایده ممکن شود.
- **معاملهٔ خودکار واقعی (CCXT)**: مثل نسخه‌های قبل، عمداً رد شد؛ این ربات فقط
  سیگنال می‌فرستد.

## مراحل نصب کامل (از صفر، با گوشی اندروید)

### مرحله ۱ — ساخت مخزن گیت‌هاب
در مرورگر گوشی وارد github.com شوید → **New repository** → نامی مثل
`quant-bot` بدهید → **Private** را انتخاب کنید (مهم، چون Secrets و منطق
معاملاتی شخصی داخلش است) → Create.

### مرحله ۲ — استخراج و آپلود فایل‌ها
با **Total Commander**: روی فایل zip دانلودشده لمس طولانی بزنید →
**Extract/Unzip** (نه Pack با آن اشتباه نگیرید) → وارد پوشهٔ استخراج‌شده شوید.
در گیت‌هاب، داخل مخزن خالی: **Add file → Upload files** → تمام فایل‌ها و
پوشه‌ها (`*.py`, `requirements.txt`, `README.md`, `.gitignore`, پوشهٔ
`.github/workflows/`, پوشهٔ `tests/`) را همان ساختار پوشه‌ای که هست آپلود
کنید. برای فایل‌های داخل `.github/workflows/bot.yml`، چون گیت‌هاب وب گاهی
مسیرهای تودرتو را در Upload مستقیم نمی‌پذیرد، اگر لازم شد این فایل را جدا
باز کنید (Add file → Create new file) و مسیر کامل `.github/workflows/bot.yml`
را در نام فایل تایپ کنید — گیت‌هاب خودش پوشه‌ها را می‌سازد.

### مرحله ۳ — ساخت GitHub Secrets (اطلاعات محرمانه)
تب **Settings** مخزن → **Secrets and variables → Actions** → **New repository
secret** → سه‌بار تکرار کنید:
- `TELEGRAM_TOKEN` = توکن رباتتان از @BotFather
- `TELEGRAM_CHAT` = آیدی عددی چت/کانال تلگرام شما
- `ENCRYPTION_KEY` = یک کلید Fernet معتبر. اگر ندارید، از سایتی مثل
  Replit یا هر ترمینال پایتون این را اجرا کنید و خروجی را کپی کنید:
  `python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`

⚠️ توکن تلگرام و کلید رمزنگاری را هرگز در چت یا جای عمومی share نکنید. اگر
قبلاً به‌اشتباه جایی share شده، حتماً از @BotFather توکن را Revoke/بازسازی
کنید.

### مرحله ۴ — تنظیمات اختیاری (GitHub Variables)
همان مسیر Settings → Secrets and variables → Actions → تب **Variables**؛
همهٔ این‌ها اختیاری‌اند (اگر نسازید، مقدار پیش‌فرض در `config.py` استفاده
می‌شود): `SYMBOLS`, `MIN_SIGNAL_PROBABILITY`, `MIN_ADX`,
`ATR_SL_MULTIPLIER`, `ATR_TP_MULTIPLIER`, `RISK_PERCENT_PER_TRADE`,
`SL_WARNING_THRESHOLD`, `SYMBOL_COOLDOWN_CYCLES`, `CYCLE_MINUTES`,
`TRAILING_TRIGGER_R`, `MAX_CONCURRENT_TRADES` (جدید در v25).

### مرحله ۵ — اجرای دستی برای تست
تب **Actions** → روی workflow با نام «AI Quant Bot v25.0 - Trading Cycle»
بزنید → **Run workflow** → چند ثانیه صبر کنید → وارد اجرای تازه شوید → مرحلهٔ
**Run Quant Engine** را باز کنید → مطمئن شوید در انتها
`✅ Cycle completed` بدون خطای قرمز آمده. اگر Secrets درست باشند، باید یک
پیام تست یا سیگنال (در صورت وجود شرایط) در تلگرامتان دریافت کنید.

### مرحله ۶ — رها کردن
بعد از تست موفق، دیگر کاری لازم نیست؛ `cron` هر ۵ دقیقه خودکار اجرا می‌شود،
حتی وقتی گوشی خاموش است — چون کل اجرا روی سرورهای گیت‌هاب انجام می‌شود، نه
روی گوشی شما.

## نکات مهم امنیتی و صداقت فنی

- این ربات فقط **سیگنال تحلیلی** ارسال می‌کند؛ هیچ سفارش خرید/فروش واقعی خودش
  ثبت نمی‌کند و به هیچ صرافی متصل نیست که بتواند پول جابه‌جا کند.
- هیچ سیگنالی تضمین سود نیست — این یک ابزار کمکی بر پایهٔ اندیکاتورهای فنی
  است، نه پیش‌بینی قطعی بازار. مدیریت ریسک (مثل درصد کوچک از سرمایه در هر
  معامله) همیشه با خود شماست.
- هرگز هیچ توکن یا Secret را در کد هاردکد یا در چت/جای عمومی به اشتراک
  نگذارید.
- در طول این پروژه، چند بار در فایل‌های آپلودی دستورالعمل‌های جاسازی‌شده
  (Prompt Injection) دیده شده که سعی داشتند مسیر کار را منحرف کنند — همیشه
  نادیده گرفته شدند. این هوشیاری در تمام نسخه‌های بعدی هم ادامه دارد.
